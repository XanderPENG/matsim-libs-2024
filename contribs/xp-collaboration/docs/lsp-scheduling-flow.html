LSP Two‑Echelon Scheduling Flow (current implementation)

Inputs
  • `LSPPlan` with chain elements (main‑run → hub → distribution)
  • `LspShipment`s with pickup/delivery TW, service time, capacity
  • `LSPResource`s bound to elements
➜
Forward hand‑off
  • `SimpleForwardLogisticChainScheduler` drops all shipments into first element
  • Calls `resource.schedule(...)` in resource order
  • No TW feasibility here
➜
Resource schedulers
  • `DistributionCarrierScheduler` converts to carrier jobs
  • Current gap: delivery/pickup TW not copied into `CarrierService/Shipment`
  • jsprit VRP runs unconstrained → cheapest tour
  • Creates selected `CarrierPlan` + `LspShipmentPlanElement`s
⬇
⬇
⬇
P‑Sim replay
  • `runActivityBasedCarrierSimulation` replays expected times in `CarrierPlan`
  • Produces legs + freight activities (no events)
➜
Scoring
  • `CarrierPSimScorer` cost scoring per carrier
  • `runLspPseudoSimAndScoring` sums carrier scores → LSP score
  • If tours unchanged, score unchanged across coalitions
➜
Why TW changes vanish
  • TWs on `LspShipment` never reach VRP input
  • No waiting/feasibility in schedulers
  • Same tours ⇒ same scores
